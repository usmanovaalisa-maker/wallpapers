# Ежедневная задача Claude на своём компьютере

Раньше эту работу делали два задания в облачной сессии Claude Code. Теперь хватит одной
запланированной задачи в Claude Desktop на вашем Mac — облачные кредиты не тратятся.
Ничего, кроме Git, устанавливать не нужно.

Как это работает: каждый день в 10:00 задача пишет фразы на завтра и делает push в GitHub.
Этот push сам запускает сегодняшние рассылки в чаты «Доброплан 2026 _ Чат руководителей» и
«НГ 2026-2027». Ключи TrueStats и Битрикс24 остаются в секретах GitHub — на компьютер их переносить не нужно.

## Шаг 1. Проект на компьютере (уже сделано)

```
cd ~/Documents
git clone https://github.com/usmanovaalisa-maker/wallpapers
```

## Шаг 2. Разрешите компьютеру отправлять изменения в GitHub (один раз)

1. В браузере откройте https://github.com/settings/personal-access-tokens/new
2. Token name: `Дари Сейчас — Mac`. Expiration: `366 days` (или «No expiration»).
3. Repository access: **Only select repositories** → выберите `wallpapers`.
4. Permissions → Repository permissions → **Contents: Read and write**.
5. Нажмите **Generate token** и скопируйте токен (он начинается с `github_pat_`). Никому его не пересылайте.
6. В Терминале:
   ```
   cd ~/Documents/wallpapers
   git config credential.helper osxkeychain
   git push
   ```
   На вопрос **Username** введите `usmanovaalisa-maker`, на **Password** — вставьте токен
   (символы при вводе не видны — это нормально) и нажмите Enter. Ответ `Everything up-to-date` —
   значит, всё получилось: Mac запомнил токен в Связке ключей и больше спрашивать не будет.

## Шаг 3. Создайте задачу в Claude Desktop

1. Откройте Claude Desktop → вкладка **Code** → выберите папку `Документы/wallpapers`.
2. Отправьте в чат:
   > Открой файл docs/local-claude-tasks.md и создай запланированную задачу «Рассылки и фразы — Дари Сейчас»: каждый день в 10:00 по часовому поясу Самары, текст — из раздела «Текст задачи».
3. Если Claude попросит разрешения, подтвердите.

## Текст задачи (каждый день в 10:00)

```
Сначала отметь запуск, потом напиши свежие фразы на ЗАВТРАШНИЙ день для бренда «Дари Сейчас» (подарки и чай): для подписчиков, для команды и для новогодней рассылки — это разные аудитории с разным тоном. Работай в папке репозитория wallpapers (GitHub usmanovaalisa-maker/wallpapers, ветка main, владелец разрешил пушить прямо в main). Сегодняшний push запустит сегодняшние рассылки, а завтра GitHub Actions так же подтянет итоги прошедшего дня из TrueStats, выберет подходящий вариант текста и отправит в Битрикс24: напутствие команде — в чат «Доброплан 2026 _ Чат руководителей» (итоги по магазинам «Дари Радость» и «Дари сейчас»), новогоднюю рассылку — в чат «НГ 2026-2027» (итоги только группы артикулов «НГ27_ВБ» + итоги с начала сезона). Формат сообщения: основной текст → строка с реальными цифрами → поддерживающая фраза с пожеланием (она же на картинке). Сайт https://usmanovaalisa-maker.github.io/wallpapers/ весь день показывает фразы подписчикам.

Шаги:
1. `git fetch origin main && git checkout main && git reset --hard origin/main` (локальных изменений быть не должно). Определи ЗАВТРАШНЮЮ дату в часовом поясе Europe/Samara (ДАТА = ГГГГ-ММ-ДД) и её день недели. Запиши в файл .github/last-local-run текущие дату и время по Самаре (одной строкой) — этот файл коммитится всегда, даже если фраз писать не нужно: его push запускает сегодняшние рассылки в Битрикс24.
2. Проверь каждый файл отдельно: если в wishes/fans.json уже есть daily[ДАТА] — шаг 4 пропусти; если в wishes/team.json уже есть daily[ДАТА] или в его calendar нет ключа ДАТА (не рабочий день) — шаг 5 пропусти; если в wishes/ng.json уже есть daily[ДАТА] или ДАТА не рабочий день (нет в calendar team.json) — шаг 5б пропусти. Если всё пропущено — сразу переходи к шагу 8 (закоммить только .github/last-local-run).
3. ПОДПИСЧИКИ — поводы. Найди через веб-поиск поводы ДАТЫ, но используй ТОЛЬКО те, что близки бренду: подарки и сюрпризы (день подарков, сюрпризов, объятий, комплиментов, доброты, благодарности и т.п.); поводы для радости и тёплые семейные праздники (день улыбки, день мамы/папы/бабушек и дедушек, день семьи, друзей, влюблённых, 8 Марта, 23 Февраля, первый снег, начало сезона); всё детское (день защиты детей, каникулы, школьные праздники, сказки и игры, день мороженого, конфет и сладостей); новогоднее и зимние праздники (подготовка к Новому году, Дед Мороз, ёлка, мандарины, Рождество, Старый Новый год). Остальные поводы (профессиональные дни, технологии, интернет, наука, спорт, памятные даты и т.п.) НЕ упоминай. Никогда не касайся политики, войн, трагедий, болезней, религиозных споров, скандалов, чужих брендов и знаменитостей. Если подходящего повода нет — пиши про сезон, день недели, уют, чай, заботу, подарки и маленькие радости.
4. Подписчикам (wishes/fans.json): добавь daily["ДАТА"] = массив из 12 новых фраз. Обращение на «ты», 1 предложение (иногда 2), до 110 символов, тепло, без пафоса и канцелярита, можно лёгкий юмор; если есть подходящий повод — 4–6 фраз про него, остальные — про сезон, подарки и добрые пожелания. Если фраза зависит от рода — нейтральная формулировка или «рад(а)». Без эмодзи и хэштегов. «Сегодня» = ДАТА. Проверь орфографию.
5. Команде (wishes/team.json): daily["ДАТА"] = ОБЪЕКТ с семью полями. Основной текст (перед цифрами): "record" — вчера лучший результат по заказам за месяц; "up" — вчера больше заказов, чем днём раньше; "steady" — примерно как раньше; "support" — спад или данных нет (поддержка без упрёков, без цифр, текст самодостаточный). Фраза после цифр (она же на картинке): "reaction_record", "reaction_up", "reaction_steady" — 1–2 предложения, до 150 символов: тёплая реакция на результат и пожелание на сегодня. Основные тексты: на «вы»/«команда»/«коллеги», 1–3 предложения, до 200 символов, цифр НЕ пиши. Понедельник — итоги за пятницу и выходные («прошлые дни») + настрой на неделю; пятница — спасибо за неделю и хороших выходных; последний рабочий день месяца — итоги месяца. Праздники подписчиков не тащи. Если calendar[ДАТА] посвящён празднику или событию — сохрани этот повод в основных текстах.
5б. Новогодняя рассылка (wishes/ng.json): daily["ДАТА"] = ОБЪЕКТ с теми же семью полями, тема — новогодний сезон и результаты новогодней коллекции (группа «НГ27_ВБ»): «рекорд сезона», рост новогодних продаж, стабильный темп сезона; образы — Дед Мороз, сани, ёлка, гирлянды, снег, подарки, мандарины, «каждый заказ — чьё-то праздничное утро». Тон бодрый, праздничный, без цифр, те же длины и правила для понедельника/пятницы.
6. Неповторимость: новые тексты не должны совпадать или быть почти одинаковыми ни с одной фразой в этих трёх файлах (включая поля внутри объектов). Проверь скриптом на Python (нормализованный текст и difflib ratio > 0.8) и замени похожие.
7. Сохрани JSON (UTF-8, ensure_ascii=False, indent=1 для team.json и ng.json; в fans.json вставляй блок текстом, не пересериализуй весь файл). Проверь json.load для всех трёх файлов и что `WISH_DATE=ДАТА DRY_RUN=1 python3 scripts/send_bitrix.py` и `WISH_DATE=ДАТА DRY_RUN=1 WISHES_FILE=wishes/ng.json python3 scripts/send_bitrix.py` отрабатывают без ошибок. Больше ничего не меняй (кроме .github/last-local-run).
8. Закоммить с сообщением «Свежие фразы на ДАТА» (или «Запуск рассылок», если менялся только .github/last-local-run) и сделай `git push origin main` (при отказе — `git pull --rebase origin main` и повтори до 4 раз). Push запустит рассылки в GitHub Actions; повторно в тот же день они не отправятся.
9. Кратко перечисли повод дня и добавленные тексты.
```

## Если компьютер выключен

- Фразы на завтра не напишутся — уйдут запасные тексты из календаря (ничего не сломается).
- Рассылку в этот день запустит расписание GitHub Actions (10:00), но иногда с опозданием на несколько часов.
  Повторной отправки не будет — перед отправкой проверяется, отправляли ли сегодня.
- Push раньше 10:00 рассылку не запускает (чтобы TrueStats успел обновить цифры за вчера).
